# 05 配置手册（零基础版）—— 从零把 MES 跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；技术细节与架构，看工程 [README](../README.md) 与 [docs/01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL** | 数据库，所有业务数据存在这里 | 大仓库的账本 |
| **Redis** | 缓存，存登录会话等临时数据 | 门卫的登记本 |
| **JDK 21** | Java 运行环境，后端 jar 包需要它 | 播放器（jar 是影碟） |
| **Maven** | Java 的打包工具，把源码编译成 jar | 印刷厂 |
| **Node.js** | 前端页面的构建运行环境 | 网页的发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **单体 / 微服务** | 两种安装形态：单体=所有功能装在一个程序里；微服务=拆成多个程序各司其职 | 便利店 vs 购物中心 |

> **新人建议选「单体」**：一个程序 + MySQL + Redis 就能跑全部功能（含 MES）。微服务是给有运维团队的正式生产环境用的（见第九节）。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或拿到压缩包） | jar 也可以直接找开发要成品 |

## 三、路线 A：容器一键部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker

- Windows：安装 Docker Desktop 并启动；Linux：安装 docker + docker compose 插件。
- ✅ 成功标志：命令行执行 `docker --version` 能输出版本号。

### 第 2 步：启动数据库和缓存

命令行进入仓库的 `mse-framework/docker` 目录，执行：

```bash
docker compose up -d mysql redis
```

- ✅ 成功标志：`docker ps` 里出现 `mse-mysql`、`mse-redis` 两个容器，状态 Up（首次要等 MySQL 初始化约 1 分钟）。
- 说明：这一步会创建两个空数据库——`mse_platform`（平台控制面）和 `mse_tenant`（租户业务库），**不用你手工建表**。

### 第 3 步：启动应用（单体，含 MES 全部功能）

仍在同一目录执行（首次会构建镜像，10~20 分钟属正常）：

```bash
docker compose --profile apps up -d --build mse-monolith
```

- ✅ 成功标志：浏览器打开 `http://localhost:8080` 能看到服务应答；`docker logs -f mse-monolith` 里出现 `Started ... in xx seconds`。
- MES 的业务表、9 个业务角色、菜单与权限点，都会在启动时**自动写入数据库**，无需执行任何 SQL。

### 第 4 步：启动网页前端

前端是独立的网页工程，需要 Node.js：

```bash
cd mse-framework/mse-ui      # 基座门户（含 MES 页面）
npm install
npm run dev
```

- ✅ 成功标志：浏览器打开 `http://localhost:3000` 看到登录页。

### 第 5 步：登录平台，开通租户

1. `http://localhost:3000` 用**平台超管**登录：账号 `platform`，密码 `admin123`（正式环境务必改密码）。
2. 「租户管理」→ 新建租户 → 按向导填写，系统会自动生成该租户的管理员账号。
3. （可选）想要现成演示数据：执行 `mse-framework/docker/mysql/demo/` 下的 `02_demo_tenant.sql` 与 `03_demo_tenant_identity.sql`，得到示例租户 `demo.mse.local`（租户管理员 `admin/tenant123`）。

### 第 6 步：给租户"点亮" MES（关键！不勾菜单看不到系统）

用平台账号进「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**制造执行**」分组下的页面菜单（基础数据/生产计划/生产执行/报工工作台/质量管理/设备管理/物料管理/追溯查询/看板报表，以及二三四期的 AI 智能化设置、系统集成、设备数采监控、安灯管理、SPC 分析）→ 保存。

- ✅ 成功标志：用**租户管理员**重新登录后，左侧出现「制造执行」菜单组。
- 原理：MES 的菜单默认是"封存"的，套餐勾选是租户可见的总开关。

### 第 7 步：给员工分配 MES 角色

1. 用**租户管理员**登录 → 「组织管理」→「用户管理」新建员工账号、建好部门（建议按"车间→班组"建部门树）。
2. 「角色管理」里能看到 9 个预置角色（随启动自动种入）：`mes_admin` MES系统管理员、`mes_planner` 计划员、`mes_dispatcher` 调度员、`mes_leader` 车间主任、`mes_operator` 操作工、`mes_inspector` 质检员、`mes_equipment` 设备管理员、`mes_warehouse` 仓管员、`mes_executive` 管理层。
3. 给每个用户勾选对应角色（可多选）。权限细节见 [03-角色规划](03-角色规划.md)。

### 第 8 步：验收 MES 主流程

按 [04-操作说明书](04-操作说明书/README.md) 的顺序走一遍：基础数据建模 → 建生产订单 → 下达 → 派工 → 报工 → 检验 → 看板。走通即部署成功。

## 四、常用配置项速查（单体形态）

> 单体的配置文件：`mse-sample/mse-monolith/src/main/resources/application.yaml`。可用**环境变量**覆盖，不用改文件（容器方式已在 compose 里预置）。

| 想改什么 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 数据库地址 | `MSE_MYSQL_HOST` / `MSE_MYSQL_PORT` | localhost / 3306 | 用你自己的 MySQL 时改 |
| 数据库账号/密码 | `MSE_MYSQL_USER` / `MSE_MYSQL_PASSWORD` | root / 123456 | 账号需有建库权限（系统自动建 `mse_tenant`、`mse_platform`） |
| 缓存地址 | `MSE_REDIS_HOST` / `MSE_REDIS_PORT` | localhost / 6379 | 密码同机默认无 |
| 服务端口 | —（配置文件 `server.port`） | 8080 | 网页接口统一入口 |
| 前端代理目标 | `mes-ui/vite.config.ts` 里 target | http://localhost:8080 | 前端开发时接口指向 |

> 数据库建表、升级、种子数据全部**随启动自动执行**（版本化脚本，重复启动不会重复执行）。升级新版本 = 换新 jar 再启动，脚本自动补齐增量。

## 五、前端（MES 子应用）的两种跑法

MES 网页不是独立网站，而是"挂"在基座门户里的子应用（微前端）：

1. **开发调试**：`cd mse-modules/mse-mes/mes-ui && npm install && npm run dev`，启动在 `http://localhost:4020`；在基座「子应用管理」界面把 mes 子应用的开发地址登记为 `//localhost:4020`，刷新门户即可嵌入使用。
2. **正式部署**：`npm run build`，产物按 `/sub-apps/mes/` 路径部署到静态服务器（构建已内置该前缀），子应用登记为生产地址 `/sub-apps/mes/`。

> 前提：第 6 步的套餐勾选已完成，否则页面登记了也看不见菜单。

## 六、开启 AI 能力（可选，默认关闭）

MES 的 AI 按钮（AI 日报、AI 诊断、AI 排产建议、智能问数、SOP 问答等）**出厂是关闭的**（按钮置灰）。按二选一开启：

### 方式一：接 AI 服务平台（推荐，功能全）

1. 部署本仓库的 mse-ai 工程（单体形态：聚合工程里加入 ai-service 后重新启动即可）。
2. MES 的 8 个场景智能体（`mes_report_writer` / `mes_quality_diag` / `mes_equip_diag` / `mes_data_analyst` / `mes_schedule_advisor` / `mes_kb_qa` / `mes_andon_summary` / `mes_spc_interpret`）**无需手工创建**——由 MES 模块随服务启动自动注册到 mse-ai「智能体管理」（默认已发布，问数智能体已绑定 `mes_query` 受控取数工具）；如需调整提示词或绑定模型/知识库，到「智能体管理」编辑本租户副本。
3. 在基座「**参数设置**」把参数 `mes.ai.mode` 的值改为 `platform`（仅走 AI 服务）或 `auto`（AI 服务优先、失败回退直连）。
4. 到 MES 的「AI 智能化设置」页核对能力状态为"可用"；各场景默认映射即上述同名智能体，仅在想换用自建智能体时才需要调整映射。

### 方式二：直连大模型（轻量）

1. 在配置里提供 OpenAI 兼容参数（`spring.ai.*`：base-url、api-key、model 等；容器环境用环境变量注入）。
2. 「参数设置」把 `mes.ai.mode` 改为 `direct`。

> ✅ 成功标志：各页面 AI 按钮点亮；AI 输出弹窗底部带「AI 生成，仅供参考」标注。`off`/未配参数时按钮置灰属正常。

## 七、对接 ERP / 上游系统（可选）

全部在 MES 页面「**系统集成**」里配置（无需改配置文件）：

1. **入站（ERP → MES）**：打开「启用入站同步」。ERP 侧经开放平台调用 MES 开放接口推送订单/物料/BOM——先在开放平台（mse-open）创建应用并授权 MES 的开放能力，把凭证给 ERP 对接方。
2. **工单完工通知**：工单完工经框架通知中枢群发——在基座系统管理「通知渠道设置」为 (mes, ORDER_FINISHED) 配置路由，勾选内置 webhook 即可群机器人送达（原「结果回传」出站配置已退役，2026-10-20）。
3. 排查：「系统集成」页下半的同步日志支持按方向/类型/状态检索。

## 八、接入设备数采 IoT（可选，三期功能）

1. 「设备数采监控 → 设备配置」：为每台设备**启用监控**并填写**额定小时产量**（OEE 性能因子用）。
2. 车间 IoT 网关按以下语义调用上报接口（需预先为网关建一个登录账号换取令牌）：
   - 接口：`POST /mes/iot/collect`，JSON 报文：`{ "equipmentCode": "设备编码", "status": 状态(1运行/2待机/3维修/4停机), "outputQty": 累计产量, "collectTime": "上报时间" }`
3. 没有网关时，可用页面上的「模拟上报」验证链路（联调用）。
4. SPC 样本也可由网关按同一报文语义推送（样本来源标记为自动）。

## 九、微服务形态（进阶，多服务正式环境）

> 什么时候需要：用户量大、需要独立扩缩容、有多团队维护。门外汉/试点环境用第三节的单体即可。

1. 启动 Nacos（compose 已含）：`docker compose up -d nacos`，控制台 `http://localhost:18080`。
2. 把服务专属配置写入 Nacos：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-mes/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
3. 数据源等公共配置在共享 Data ID（`mse-micro-common.yaml`、`mse-micro-db-biz.yaml`、`mse-micro-dubbo.yaml`）里管理；MES 专属项（端口 8098、Seata 开关等）在 `mse-mes.yaml`。
4. 构建并启动服务：先在仓库根 `mvn install -DskipTests`（框架）与 mse-ai、mse-open 工程 `mvn install`（MES 依赖其契约），再 `mvn install -DskipTests -f mse-modules/mse-mes/pom.xml`，最后 `java -jar mes-boot/target/mes-boot-1.0.0-SNAPSHOT.jar`。
5. 网关路由：确认 `mse-gateway.yaml` 里有 `/mes/** → lb://mse-mes`；前端开发代理 target 改为网关地址（默认 48080）。
6. 可选开关：RocketMQ（`mq-starter` + name-server 地址）、独立库租户（平台端「租户数据源」界面维护，免重启）、信创数据库（启动参数 `--spring.profiles.active=dm` 或 `kingbase`）。

## 十、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 应用启动失败，日志报数据库连接错误 | MySQL 没起/地址密码错/账号无建库权限——`docker ps` 看容器，改环境变量后重启 |
| 日志报 Redis 连接错误 | Redis 没起或地址不对（登录会话依赖 Redis，必配） |
| 8080 端口被占用 | 改 `server.port` 或停掉占用程序（Windows：`netstat -ano | findstr 8080`） |
| 登录页打不开 | 基座前端没启动（`npm run dev`，端口 3000）或后端没起（8080） |
| 登录后左侧没有「制造执行」菜单 | 套餐没勾选 mes 菜单（见第 6 步），或该用户角色没授权菜单 |
| 登录后看得到菜单但页面空白/404 | MES 子应用没登记或地址不对（见第五节）；前端代理 target 指错了后端 |
| 菜单在但看不到某些按钮 | 该用户角色无此权限（按 04 号手册的角色对照补授权） |
| AI 按钮全部置灰 | `mes.ai.mode` 未开启（见第六节） |
| 接口报 404（微服务） | mes-boot 没注册到 Nacos，或网关路由没配 `/mes/**` |
| 界面/数据库中文乱码 | 建库与连接必须 utf8mb4（脚本已内置；自建库时确认字符集） |
| 启动日志报"脚本执行失败"并退出 | 数据库迁移是启动强校验：按日志提示修复后重启，不要跳过 |
| ERP 推单不生效 | 「系统集成」入站开关没开，或开放平台应用未授权 MES 能力 |

## 十一、上线前检查清单

- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码）

- [ ] 前端走 HTTPS 与正式域名；子应用登记改为生产地址
- [ ] 微服务形态：Nacos 开鉴权、网关白名单按需最小化
