# 02 权限规划 —— 子应用注册、页面菜单与权限点

> mse-mes 的菜单与权限点设计。功能点含义见 [01-功能规划](01-功能规划.md)，角色授权见 [03-角色规划](03-角色规划.md)。
> **本文所有 id / 号段均为规划值**，工程实际创建时按 `zcode-plugin/plugins/mse-dev/references/alloc-tables.md` 登记纪律正式占用（当前号段未被任何工程占用，无冲突）。

## 一、规划原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **sys_menu.type**：1=目录（本工程仅 500 一个分组目录）、2=基座侧普通菜单（MES 不用）、3=子应用页面菜单（`micro_name` 关联子应用、`path` 为子应用内部路由）。`menu_scope=2` 租户端。
3. **权限点必须挂靠页面菜单**：`sys_permission.menu_id` 指向本工程 type=3 页面菜单，才参与角色授权分组与**租户套餐裁剪**（`sys_tenant_package.menu_ids` 圈定菜单 → 隐含圈定挂靠的权限点）；`menu_id=NULL` 即通用权限（登录即授予）——MES 无此需求，全部挂菜单。
4. **权限码格式**：`mes:<模块>:<动作>`，模块可两级（如 `mes:qc:scheme:save`），动作小写动词，与仓库现有 `oa:form:list` / `open:app:reset-secret` 等风格一致；唯一键 `uk_code`。
5. **前端按钮控制**：子应用内用 `v-permission` 指令按权限码显隐按钮（拷 `mse-demo/demo-ui` 的 directives/permission.ts）。
6. **落库方式**：随 jar 的幂等版本化脚本 `mes-service/src/main/resources/db/<方言>/V{yyyyMMdd}_{NN}_mes__base.sql`（头指令 `-- mse-target: base`；当前随仓库惯例仅 MySQL），由 starter-bridge 自动推送 mse-system 应用——**免手工执行、不把 SQL 种子写进框架区**（基座基线随 service-system jar 自带）；已应用脚本不再修改，变更一律新增版本文件。

## 八、套餐裁剪与登记纪律

1. **租户套餐**：mes 页面菜单（501-514）需在平台端「套餐管理」勾选后才对租户可见；租户管理员拿到的是「套餐域内全量权限码」，裁剪对管理员同样生效。未配置任何页面菜单的中间状态会退化为单菜单项渲染，建议 501-509 一次配齐。
2. **网关白名单**：车间大屏若做免登录只读视图，相关接口按需追加 `mse.gateway.ignore-urls`（注意 Spring list 属性整体替换，须全量列出）。
3. **alloc-tables.md 登记**（工程创建时执行，本规划仅标注不占号）：后端端口 8098、前端 dev 4020、micro_app id=11、菜单段 500-514、权限段 4401-4487、网关前缀 `/mes`、sys_config 种子 id 53200+。
4. **脚本纪律**：全部幂等写法（菜单按 id 判重、权限点按 id 判重，参照 `mse-oa/oa-service/.../db/mysql/V20260922_01_oa__oa_base.sql`）；历史挂靠修正用条件 UPDATE 幂等补挂。
