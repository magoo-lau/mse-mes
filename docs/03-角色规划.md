# 03 角色规划 —— 角色定义、授权矩阵与数据权限

> mse-mes 的角色与授权设计。权限点 id / code 见 [02-权限规划](02-权限规划.md)，功能点含义见 [01-功能规划](01-功能规划.md)。
> 角色种子与授权绑定随工程落地为幂等版本化 SQL，**本文表格即种子数据的直接输入**。

## 一、角色模型说明

1. **全部为租户级角色**（`sys_role.tenant_id` = 当前租户）：MES 是租户端子应用（side=1），不涉及平台端角色；平台「平台运营」角色与本产品无关。
2. **租户超管不依赖角色**：`sys_user.super_admin=1` 的租户管理员天然拥有套餐域内全量权限码，本清单角色面向**业务岗位**分工。
3. **角色受套餐裁剪约束**：即使授予 mes_admin，其权限也以租户套餐勾选的 mes 菜单（501-514）为上界（见 [02-权限规划](02-权限规划.md) 第八节）。
4. **种子是起点不是终点**：种子 SQL 提供「开箱即用」的默认授权，租户管理员可在基座「角色管理」中按需微调（角色保存授权集合语义：传 null 保持不变、非 null 全量替换）。
5. **MES 系统管理员 ≠ 租户超管**：mes_admin 只管 MES 业务域（建模/AI 设置/集成配置），不涉及用户、角色、系统管理等基座能力。

设计要点：

- **报工闭环双签**：操作工提交（4433）→ 调度员/车间主任审核（4435），审核开关可配，免审租户两个角色都不授即可。
- **异常双入口分层**：操作工/调度员只能登记停工（4432），质量异常的登记/关闭（4445/4446）收口在质检员与车间主任。
- **停工查询随页必授**：生产执行页挂载即拉停工列表（4701），凡可见 503 页面的角色一律授予，否则页面顶部报「没有该操作权限」（4701 一期漏播，2026-09-27 补播）。
- **建模只收归管理员**：基础数据写权限只给 mes_admin，避免多角色并发改主数据；其他角色一律只读引用。

## 五、数据权限（data_scope）设计

| 场景 | 规则 | 依据 |
| --- | --- | --- |
| 操作工报工/领料记录 | 仅本人（5） | 个人作业数据，班组汇总走看板 |
| 调度/质检/设备/仓管的业务单据 | 本部门（3） | 部门=车间（或班组），跨车间互不可见 |
| 计划员/车间主任 | 本部门及以下（4） | 管理跨度含下属班组 |
| MES 系统管理员/管理层 | 全部（1） | 全厂视角（仍受租户隔离与套餐上界） |
| 报表统计口径 | 统计类查询按角色 data_scope 过滤数据行，看板大屏免登录视图仅呈现脱敏汇总 | 免登录视图不暴露个人级明细 |
| 跨租户 | 一律由租户插件行级隔离，与角色无关 | 多租户基线 |

## 七、种子落库规划

1. **角色属租户库表**：`sys_role` / `sys_role_menu` / `sys_role_permission` 种子放 `mes-service/src/main/resources/db/<方言>/V{yyyyMMdd}_{NN}_mes__init.sql`（缺省 `-- mse-target: master`，与业务表 DDL 同脚本或相邻版本文件），随服务启动应用到业务主库，并由租户库克隆/懒初始化通道对每个租户独立库自动就绪——免手工执行。
2. **幂等写法**：角色按 `code` 判重（`WHERE NOT EXISTS`），绑定按 `(role_id, menu_id)` / `(role_id, permission_id)` 判重；**已应用脚本不再修改**，新增角色/调整授权一律新增版本文件。
3. **角色 id 规划 11-19**：与子应用注册 id=11 同段便于记忆；落地时在 `alloc-tables.md` 登记确认（该表当前未约定角色号段，登记时与基座/其他工程核对）。
4. **菜单与权限点**：属基座库全局表，走 `db/<方言>/` 中头指令 `-- mse-target: base` 的脚本由 starter-bridge 推送（见 [02-权限规划](02-权限规划.md) 第一节），与角色种子分离。
5. **AI 场景映射种子**：AI 智能体（`mes_report_writer` 等）由 mse-ai 侧种子承载，MES 侧仅存场景→agentCode 映射（AI 设置页配置，落 `sys_config` 参数或自有配置表均可，落地时定）；`mes.ai.mode` 开关参数规划 id=53200（各库默认模板行，本租户覆盖行优先）。
