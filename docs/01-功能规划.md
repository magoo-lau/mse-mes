**一期核心业务闭环**：

```
建模（产线/物料/BOM/工艺/日历）
  → 生产订单 → 排产（产线×班次）→ 下达
  → 派工（工位/人员）→ 领料（线边仓）
  → 工序开工 → 报工（数量/合格/不良）→ 工序转移 → … → 完工
  → 检验（IPQC/FQC）→ 不良处置（返工/报废/让步）
  → 完工入库/批次追溯 → 看板与报表
```

## 二、基础数据建模（一期）

所有主数据按租户隔离；建模数据是后续派工、报工、追溯的引用基础。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 工厂/车间/产线/工位建模 | 四级制造模型树，工位绑定设备与默认操作工 | MES 系统管理员 |
| 物料主数据 | 物料编码/名称/规格/单位/类型（原料/半成品/成品），批次与序列号管理策略（按批次/按件） | MES 系统管理员 |

| 工艺路线管理 | 工序定义（工步、标准工时、质检点标记），产线×产品的工艺路线维护与版本发布 | MES 系统管理员 |

## 十三、AI 智能化特色功能（二期起，专项）

### 13.1 设计原则 —— 对齐平台 AI 范式（mse-oa × mse-ai 同款）

**MES 不自建 AI 能力；模型通道平台优先、直连兜底。** 全部 AI 场景复用仓库已有的两层 AI 底座：

1. **正向（MES 调 AI）**：`mes-service` 依赖 `ai-api` 契约 → `@RpcReference RemoteAiChatService` → `chat(AiChatRequest{agentCode, message, variables})`（同步非流式满足日报/诊断类一次性生成）；流式场景（问答）前端直接走网关 `/ai/chat/stream` SSE。
2. **反向（AI 调 MES）**：MES 实现 `RemoteAiTool`，以「一服务一工具」门面 `mes_query`（group=`mse-mes`）导出，schema 内 `action` 枚举分发；单体形态平台自动收集容器内 Bean。
3. **能力开关**：基座「参数设置」sys_config 参数 **`mes.ai.mode`**（两端独立：各库默认模板行规划 id=53200，本租户覆盖行优先）——`off`（默认）/ `auto`（平台优先失败回退直连）/ `platform` / `direct`（starter-ai 的 `mseChatClient` + OpenAI 兼容协议，未配 `spring.ai.*` 时零装配）。
4. **场景→智能体映射**：AI 智能化设置页（页面菜单 510）下拉选择 mse-ai 已发布智能体按场景映射，租户隔离、保存即生效（对齐 OA v3 模式）。各场景默认智能体由 `MesAiAgentProvider` 声明（`AiAgentProvider` 契约），随服务启动自动登记 mse-ai 智能体管理（单体启动扫描 / 微服务周期重推，幂等；平台行为登记本体、各租户首次使用懒补齐可编辑副本），管理员无需手工创建同名智能体。
5. **红线**：AI 只出**草稿/建议**，一切写操作（排产下达、处置执行、日报发布）必须人工确认；AI 输出页统一标注「AI 生成，仅供参考」；绝不让模型直连业务库拼 SQL——数据供给全部经写死语义的反向工具。

### 13.3 MES 反向工具 `mes_query`（供 AI 智能体受控取数）

门面工具 + action 枚举分发（对齐 `oa_flow` / `data_query` 模式），入参/出参均为 JSON 字符串：

| action | 供数内容 | 说明 |
| --- | --- | --- |
| `order_progress` | 工单进度（状态/完工数/合格数/交期） | 支持按产线/时间段/状态过滤 |
| `production_stats` | 产量统计（产线×班次×时段） | 聚合口径在 Mapper 内写死 |
| `quality_stats` | 质量统计（合格率/不良 TOP） | 同上 |

| `wip_query` | 在制品分布 | 工序维度的滞留明细 |

工具实现放 `mes-service`（数据经本模块 Mapper 查询，天然带租户隔离）；微服务形态在 `mes-boot` 以 group=`mse-mes` 导出，登记 mse-ai `ai_tool`（工具 id 规划在 mse-ai 现有 8101/8102 之后顺延，落地时与 mse-ai 工程对齐）。
